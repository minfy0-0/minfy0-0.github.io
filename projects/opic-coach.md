## 녹음한 답변을 고치고, 다시 말할 수 있도록

OPIc를 준비할 때 질문 자료를 찾는 곳, 스크립트를 쓰는 곳, 녹음하고 피드백을 받는 곳이 달랐습니다. 질문을 듣고 답한 뒤, 무엇을 고칠지 확인하고 다시 연습하는 과정을 한 화면 흐름으로 만들고 싶었습니다.

개인 프로젝트로 요구사항, 화면 흐름과 데이터 구조를 정하고 API 연결과 구현을 진행했습니다. 코드 작성과 오류 분석에는 ChatGPT 등 AI 도구를 활용했습니다. 수정 뒤에는 제가 직접 연습해 보며 화면과 응답이 의도대로 동작하는지 확인했습니다.

연습은 다음 순서로 이어집니다.

1. 주제를 고르고 질문을 음성으로 듣습니다.
2. 답변을 녹음하고, 자동 전사된 텍스트를 확인하거나 수정합니다.
3. 항목별 피드백과 수정 예시를 읽고 다시 연습합니다.
4. 로그인한 사용자는 자신의 스크립트와 연습 기록을 저장합니다.

## 공용 질문은 바로, 개인 기록은 사용자별로

바로 연습을 시작하는 흐름과 개인 자료를 보관하는 흐름을 나눴습니다. 게스트는 로그인 없이 공용 질문으로 연습할 수 있고, 로그인한 사용자는 자신의 스크립트와 이전 답변을 저장할 수 있습니다.

공용 문제은행에는 **활성 주제 166개와 활성 질문 219개**를 구성했습니다. 주제와 질문은 공용 데이터로, 스크립트·연습 기록·프로필은 사용자별 데이터로 나눴습니다. Supabase Auth, Postgres, Row Level Security로 개인 기록의 접근을 구분하고 이메일·카카오 로그인을 연결했습니다.

이 수치는 이 글에 정리한 문제은행의 규모입니다. 이용자 수나 학습 효과를 나타내지는 않습니다.

## AI가 답변을 잘못 읽었을 때, 사용자가 고칠 수 있게

질문 음성에는 Orpheus의 Hannah voice, 답변 전사에는 Whisper Large V3 Turbo, 피드백에는 GPT-OSS-120B를 연결했습니다. 질문을 텍스트로 먼저 읽지 않고 듣도록 했으며, 질문 음성은 최대 두 번 재생할 수 있습니다.

녹음 전에는 마이크 테스트로 입력 레벨을 보고 짧게 녹음한 목소리를 다시 들을 수 있습니다. 권한이나 입력장치 문제를 연습 전에 확인하기 위한 기능입니다.

자동 전사도 그대로 평가에 넘기지 않았습니다. 음성 인식이 틀리면 실제로 말한 내용과 다른 피드백을 받을 수 있어, **사용자가 전사문을 확인하고 수정한 뒤 평가를 요청하도록** 했습니다.

## 점수보다 ‘왜 그런 점수인지’가 필요했습니다

직접 받아본 피드백에는 문법 점수가 낮은 이유가 부족하거나 한국어 설명 중간에 영어가 섞이는 문제가 있었습니다. 다음 답변을 고치는 데 쓸 수 있도록 평가 항목, 점수의 이유, 수정 예시를 나눴습니다.

| 평가 항목 | 확인하는 내용 |
| --- | --- |
| 질문 적합도 | 질문의 핵심 요구에 답했는지 |
| 자연스러움 | 답변의 흐름과 표현이 자연스러운지 |
| 문법 | 의미 전달에 영향을 주는 문장 구조·동사 오류가 있는지 |
| 시제 | 질문에 필요한 시제를 선택하고 유지했는지 |

네 항목은 각각 0–100점으로 표시하고 이유를 붙였습니다. 문법은 말하기에 영향을 주는 문제를 최대 세 개 골라 원문, 수정문, 바꾼 이유를 보여줍니다. 시제는 질문에서 기대하는 시제와 실제 사용 결과, 잘 쓴 예시와 수정할 문장을 따로 확인할 수 있게 했습니다.

기준 스크립트가 있는 연습에서는 원문 일치율만 보지 않았습니다. **핵심을 유지해 바꿔 말한 표현과 빠진 내용을 구분**하고, 내용 반영 정도와 문장별 비교를 함께 보여주도록 했습니다.

### 프롬프트를 고쳐도 남는 오류는 응답 뒤에서 확인했습니다

| 실제 응답에서 확인한 문제 | 반영한 처리 |
| --- | --- |
| 한국어가 필요한 설명이 영어로 반환됨 | 필드 검사 후 한 번 보정 요청. 해결되지 않으면 준비한 한국어 안내 표시 |
| 요청한 100점 척도 대신 5점 척도 등으로 반환됨 | 점수를 100점 기준으로 정규화 |
| 발음이 같은 단순 표기 차이가 문법 오류로 포함됨 | 해당 항목을 오류 목록에서 제외하는 후처리 |

프롬프트 수정만으로 해결됐다고 판단하지 않고, 실제 응답을 보며 검사·보정·대체 안내를 추가했습니다.

## 질문도 하나씩 섞기보다 상황 안에서 이어지게

처음에는 문제를 무작위로 뽑았지만 연습의 흐름이 어색했습니다. 모의고사는 배경 설문 주제, 돌발, 롤플레이, 어드밴스 순서로 조합하도록 바꿨습니다.

| 연습 구간 | 구성한 흐름 |
| --- | --- |
| 배경 설문·돌발 주제 | 같은 주제의 묘사 → 루틴·습관 → 경험 질문 |
| 11–13번 롤플레이 | 하나의 상황에서 정보 요청 → 문제 해결 → 비슷한 과거 경험 |
| 14–15번 어드밴스 | 비교·변화·이슈·해결책 질문과 시제 힌트 |

공원 약속, 쇼핑, 콘서트, 집 수리, 여행·호텔 등 관련 질문을 같은 상황으로 묶었습니다. 모의고사는 비용과 기록 관리를 고려해 로그인 사용자에게 제공했습니다. 이 구성은 서비스에서 설계한 연습 방식입니다.

## 직접 쓰면서 바꾼 부분

연습 기능 외에도 문제은행 로딩 실패 시 재시도, 한국어 인증 안내, 다크 모드, 닉네임 수정 기능을 보완했습니다. 대시보드에는 누적 연습, 평균 질문 적합도·문법 점수, 저장한 스크립트 수를 모아 이전 연습을 찾아볼 수 있게 했습니다.

사용 확인은 **연습 흐름과 기록 기능의 동작, 피드백의 응답 형식**을 중심으로 진행했습니다. 공식 시험 점수 예측 성능이나 학습 효과는 측정하지 않았습니다.
