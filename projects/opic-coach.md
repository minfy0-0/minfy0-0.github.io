## 직접 연습하면서 불편했던 점부터 만들었습니다

OPIc를 준비하면서 질문 자료, 개인 스크립트, 말하기 연습, 피드백, 기록이 각각 따로 있어 여러 도구를 오가야 했습니다. 그래서 **질문을 듣고 직접 답한 뒤 피드백을 확인하고 다시 연습하는 과정**을 한곳에 모으기로 했습니다.

질문을 찾고 녹음 도구를 켠 다음 피드백을 따로 받던 과정을, 다음 흐름으로 연결했습니다.

1. 공용 문제은행에서 주제 선택
2. 실전 모드 / 암기 모드 선택
3. 기준 스크립트 없이 연습하거나 내 스크립트 불러오기
4. 질문을 화면에 노출하지 않고 음성으로 듣기
5. 사용자가 직접 RECORD / STOP으로 답변 녹음
6. Whisper로 음성을 전사하고 필요한 경우 직접 수정
7. 세분화된 AI 피드백 확인
8. 로그인 사용자의 스크립트·연습 기록 누적

직접 써보니 녹음 전에 마이크를 확인하거나, 이전 답변을 다시 찾는 기능도 필요했습니다. 모의고사와 다크 모드, 마이크 테스트 등을 추가하고 피드백 문구와 로그인 흐름도 다듬었습니다.

## 질문은 함께 쓰고, 연습 기록은 따로 저장했습니다

공용 문제은행에는 **166개 활성 주제와 219개 활성 질문**을 넣었습니다. 같은 주제를 다시 연습할 때도 질문이 조금씩 달라지도록 여러 표현을 묶어뒀습니다.

데이터는 다음처럼 역할에 따라 분리했습니다.

- `topics` — 공용 문제 주제
- `questions` — 공용 질문
- `scripts` — 로그인 사용자별 개인 스크립트
- `practice_records` — 사용자별 전사·피드백·연습 기록
- `profiles` — 사용자 프로필 / 닉네임

문제은행은 게스트도 사용할 수 있게 열어두고, 개인 스크립트와 연습 기록은 **Supabase Auth + Postgres + Row Level Security**로 사용자별 접근을 분리했습니다. 이메일·카카오 로그인을 지원하고, 로그인하지 않아도 게스트 모드로 바로 연습할 수 있습니다.

## 질문을 듣고 답하는 흐름을 만들었습니다

질문은 텍스트를 먼저 보여주지 않고 음성으로 제공합니다. 질문 음성은 **Hannah voice**로 고정했고, 사용자는 최대 2회까지 질문을 들을 수 있습니다.

연습 전에 브라우저 마이크가 정상적으로 동작하는지 확인할 수 있도록 별도의 **Mic Check**도 추가했습니다. 입력 레벨을 실시간으로 보여주고 짧게 녹음한 목소리를 다시 들을 수 있어, 실제 연습 전에 권한·입력장치 문제를 확인할 수 있습니다.

답변 녹음 후에는 **Whisper Large V3 Turbo**로 전사합니다. 자동 전사 결과가 완벽하지 않을 수 있으므로 AI 피드백 전에 사용자가 텍스트를 직접 수정할 수 있게 했습니다.

## 무작위 문제만으로는 연습 흐름이 어색했습니다

처음에는 문제를 무작위로 뽑았지만 실제 시험 흐름과 차이가 컸습니다. 그래서 **배경 설문 주제 → 돌발 → 롤플레이 → 어드밴스** 순서를 반영해 조합 로직을 다시 만들었습니다.

### 선택한 주제는 세 질문으로 이어지게

사용자가 선택한 배경 설문 주제를 바탕으로 같은 주제 안에서 다음 3문제 흐름을 우선 구성합니다.

- 묘사
- 루틴·습관
- 경험

카페, 공원, 해변, 음악·콘서트, 술집·바, 조깅·걷기, 집, 여행, 쇼핑, 집에서 보내는 휴가 등의 주제를 현재 문제은행과 연결했습니다.

### 돌발 주제도 같은 흐름으로

배경 설문 외 돌발 주제도 별도 family로 구성했습니다. 현재 날씨, 인터넷, 은행, 재활용, 음식점 등의 주제를 묘사·루틴·경험 흐름으로 조합합니다.

### 11–13번은 하나의 롤플레이 상황으로

롤플레이는 한 문제씩 무작위로 섞기보다 하나의 상황을 기준으로 연결합니다.

- 11번: 정보 요청
- 12번: 문제 해결
- 13번: 비슷한 과거 경험

공원 약속, 쇼핑 약속, 콘서트, 집 수리, 여행·호텔, 은행 등의 상황을 같은 family로 묶었습니다.

### 14–15번은 비교와 변화에 대한 질문으로

비교, 변화, 이슈, 해결책 등 상대적으로 복합적인 주제를 별도로 분리하고 질문의 시간 조건에 맞춰 **현재·과거·현재완료 중 어떤 시제를 우선해야 하는지** 힌트를 함께 설계했습니다.

모의고사는 개인 연습보다 비용과 기록 관리가 더 큰 기능이어서 **로그인 사용자에게만 노출**하도록 UX도 조정했습니다.

## 점수만으로는 무엇을 고쳐야 할지 알기 어려웠습니다

처음 받은 피드백에는 문법 점수가 낮은 이유가 충분히 나오지 않거나, 설명 중간에 영어가 섞이는 경우가 있었습니다. 점수만 봐서는 다음 연습에서 무엇을 바꿔야 할지 알기 어려웠습니다. 실제 응답을 보면서 평가 항목과 설명 형식을 다시 정리했습니다.

현재 피드백은 기본적으로 다음 4축을 각각 0–100점으로 평가합니다.

| Metric | 보는 기준 |
| --- | --- |
| Question relevance | 질문의 핵심 요구에 직접 답했는지 |
| Naturalness | 답변 흐름과 말하기 자연스러움 |
| Grammar | 의미 전달에 영향을 주는 문법·동사·문장 구조 |
| Tense control | 질문에 필요한 시제를 선택하고 유지했는지 |

각 점수에는 이유를 붙였습니다. 문법은 말하기에 영향을 주는 문제를 최대 3개 골라, 원래 문장과 수정한 문장, 바꾼 이유를 함께 보여줍니다. 단순한 철자 차이보다 다음 답변에서 고칠 수 있는 부분에 집중했습니다.

시제는 별도 분석 영역으로 분리해 다음을 보여줍니다.

- 질문에서 기대되는 시제
- 실제 답변의 시제 사용 결과
- 잘 사용한 예시
- 수정하면 좋은 문장

추가로 답변 강점, 우선 개선 포인트, flow notes, OPIc tips를 제공합니다.

### 기준 스크립트가 있을 때

스크립트를 선택한 경우에는 일반 평가 외에도 다음 항목을 추가합니다.

- Script match
- Content coverage
- 맞게 재현한 내용
- 빠진 핵심 내용
- 자연스럽게 paraphrase한 표현
- 스크립트와 실제 답변의 matched / paraphrase / missing 비교

암기 모드에서는 원문 일치 여부만 보지 않고, **핵심을 유지한 paraphrase와 빠진 내용을 나눠서 확인**할 수 있게 했습니다.

## 한국어로 요청해도 영어가 섞여 나왔습니다

피드백 모델은 이 구현에서 **GPT-OSS-120B**를 사용합니다. 다만 프롬프트만으로는 일부 설명이 영어로 나오는 경우가 있어, 응답을 받은 뒤 한국어가 필요한 필드를 검사하는 로직을 추가했습니다.

한국어 설명이 빠진 경우에는 보정 요청을 한 번 더 보냅니다. 그래도 해결되지 않으면 미리 준비한 한국어 안내 문구를 보여줍니다. 프롬프트를 바꿔도 같은 문제가 남아 있어, 응답을 받은 뒤 확인하는 단계까지 추가했습니다.

또한 5점 척도처럼 잘못 반환된 점수도 100점 척도로 정규화하고, 실제 발음이 같은 단순 표기 차이는 문법 오류 목록에서 제외하는 후처리를 추가했습니다.

## 연습을 이어가면서 작은 불편도 고쳤습니다

최근에는 AI 기능뿐 아니라 서비스 자체의 사용성을 계속 손봤습니다.

- Light / Dark mode 제공
- 다크 모드 하단 배경까지 일관되게 보이도록 테마 수정
- 문제은행 로딩 실패 시 재시도 로직 추가
- 이메일 인증 메시지와 주요 인증 오류를 한국어 UX 문구로 변환
- 카카오 로그인 추가
- 사용자별 랜덤 닉네임 및 닉네임 수정
- 게스트는 빠르게 연습, 로그인 사용자는 기록과 스크립트 저장
- Dashboard에서 누적 연습, 평균 질문 적합도, 평균 문법, 저장 스크립트 수 확인

제가 직접 계속 사용하는 서비스라서 불편한 부분을 발견하면 원인을 확인하고 UI, 프롬프트, 데이터 구조를 수정한 뒤 다시 사용해 보고 있습니다.

## AI와 함께 구현하고, 직접 사용하며 확인했습니다

ChatGPT 등 AI 도구에 필요한 기능을 설명하고, 코드 작성과 오류 원인 분석을 함께 진행했습니다. 수정한 뒤에는 직접 연습해 보며 화면 흐름과 피드백이 의도대로 나오는지 확인했습니다.

특히 한국어 피드백이 깨지거나 점수 설명이 부족한 문제는 실제 응답을 기준으로 원인을 좁히고, 프롬프트와 후처리 로직을 함께 수정했습니다.

## 사용한 기술

| Layer | Stack |

## 계속 쓰는 서비스를 만들면서

처음에는 AI 피드백 기능부터 만들었지만, 실제로 사용하려면 문제은행, 인증, 저장, 음성 입력, 오류 처리까지 함께 필요했습니다. 기능을 하나씩 추가하면서 프론트엔드와 데이터 구조, AI 응답 처리까지 같이 보게 됐습니다.

특히 피드백 언어 오류와 점수 근거 부족 문제는 실제 출력 결과를 보고 수정했습니다. 프롬프트만 바꾸는 데서 끝내지 않고 검증, repair, fallback 로직을 추가해 같은 문제가 반복되지 않도록 했습니다.
