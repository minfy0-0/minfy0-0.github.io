## ‘찾아보지 않음’을 ‘0건’으로 보여주고 있었습니다

ASK1(MAP3K5) 활성 예측 경진대회를 경험한 뒤, 실험 데이터에 관련 연구 자료를 함께 붙여보고 싶었습니다. ChEMBL의 화합물·활성 데이터, Open Targets의 표적 연관 근거, ClinicalTrials.gov의 임상시험 기록을 모았습니다.

그런데 조회 화면을 만들면서 수집 범위의 차이가 드러났습니다. 활성 데이터는 ASK1을 기준으로 모았지만 임상시험은 **Selonsertib이라는 한 물질만 검색**했습니다. 모든 화합물 옆에 임상시험 수를 표시하면, 다른 화합물의 0건이 ‘조사하지 않음’이 아니라 ‘시험이 없음’으로 읽힐 수 있었습니다.

이 문제를 기준으로 수집·연결 규칙과 화면을 함께 손봤습니다. 제가 정리한 것은 API 수집 범위, 원본과 정제 데이터의 구분, 연결을 확정할 조건, 조회 화면에서 숫자를 설명하는 방식입니다. 코드 수정과 오류 분석에는 Codex를 활용하고 테스트와 실제 수집 결과를 대조했습니다.

## 세 출처의 자료를 어디까지 모았는지

| 출처 | 수집 범위 |
| --- | --- |
| ChEMBL | 화합물 1,777개 · 활성 레코드 2,576건. IC50 2,485건, Ki 91건 |
| Open Targets | ASK1의 질환·형질 연관 근거 100건 |
| ClinicalTrials.gov | Selonsertib·GS-4997로 검색한 임상시험 11건 |

조회 결과에서 원본과 연결 근거를 다시 확인할 수 있도록 Python으로 세 API를 연결하고 Snowflake에 원본을 보관했습니다. 화면은 **9월 7–8일 수집하고 9월 11일 검증·내보낸 스냅샷**을 사용하는 로컬 Streamlit 화면입니다. 실시간 공개 서비스로 운영하는 범위까지 진행하지는 않았습니다.

## 정제 결과에서 원본으로 돌아갈 수 있게

정제한 값이 이상할 때 어디서 달라졌는지 확인할 수 있도록 API 응답을 JSONL과 Snowflake RAW에 보관했습니다. 정제와 연결은 원본 위의 뷰로 구성했습니다.

| 계층 | 구성과 역할 |
| --- | --- |
| RAW | 표적·활성·화합물·질환 연관·임상시험 5개 테이블에 총 4,465건 보관 |
| STAGING | 이름·식별자·단위를 정리하는 6개 뷰 |
| MART | 활성·질환 연관·임상 연결을 조회하는 3개 뷰 |
| MONITORING | 실행 이력·변경 로그·품질검사·PDF 검토 후보 보관 |
| Streamlit | 조회 결과와 연결 근거 확인 |

STAGING과 MART는 정제 데이터를 별도로 복제해 쌓기보다 RAW를 조회하는 뷰로 만들었습니다. SQL 실행에는 Snowflake Warehouse를 사용했습니다.

## 빠진 Ki와 반복 적재를 각각 확인했습니다

처음에는 IC50이 수집 제한을 모두 채워 Ki가 빠졌습니다. Codex와 코드를 확인하니 두 측정 유형에 같은 제한을 적용하고 있었습니다. 유형별 제한과 페이지네이션을 나누고 회귀 테스트와 재수집 결과에서 **Ki 91건**이 들어오는 것을 확인했습니다.

적재는 행별 처리에서 묶음 처리로 바꾸고, RAW 변경과 변경 로그가 파일별 트랜잭션 안에서 함께 기록되도록 했습니다. 같은 데이터를 다시 넣은 결과는 **신규 0건 / 변경 0건 / 동일 4,465건**이었습니다. 로컬과 DB를 대조했을 때 ID·콘텐츠 해시 불일치와 ID 중복도 0건이었습니다.

품질검사에서는 오류와 경고를 구분했습니다.

| 확인 항목 | 기록된 결과 |
| --- | --- |
| 검사 9개 중 오류 등급 7개 | 실패 건수 0 |
| 활성값 누락 | 12건 |
| 원천 데이터의 중복 가능성 표시 | 196건 |

원천에서 중복 가능성이 표시된 196건은 재적재로 생긴 중복과 다릅니다. 경고 항목끼리 겹칠 수도 있어 건수를 단순 합산하지 않았습니다.

## 이름이 일치한 9건과 약어 검토가 필요한 2건

Selonsertib의 ChEMBL ID는 **CHEMBL3916717**이며, 수집한 ASK1 활성 레코드는 204건입니다. 이 물질의 이름·동의어와 임상시험 중재명에서 양끝 공백과 대소문자를 정리한 뒤 정확히 일치하는 기록을 연결했습니다.

수집한 시험 11건 중 **고유 임상시험 9건**이 연결됐습니다. 별칭별 일치 결과는 15행이었습니다. 같은 시험이 여러 이름과 일치할 수 있으므로 15개 일치 행과 9개 시험을 따로 표시했습니다.

남은 NCT03449446과 NCT04026165에서는 **SEL**이라는 약어가 기존 규칙과 일치하지 않았습니다. Codex가 공식 연구계획서에서 약어 정의를 찾고, Python으로 인용문·PDF 페이지·문서 해시·출처를 대조했습니다.

- [NCT03449446 연구계획서](https://cdn.clinicaltrials.gov/large-docs/46/NCT03449446/Prot_000.pdf): PDF 23쪽
- [NCT04026165 연구계획서](https://cdn.clinicaltrials.gov/large-docs/65/NCT04026165/Prot_000.pdf): PDF 22쪽

두 후보 모두 원문 대조는 통과했습니다. 다만 약어가 문서에 등장한다는 사실만으로 최종 연결을 확정하지 않았습니다. **EVIDENCE_MATCHED / 의미 검토 PENDING**으로 보관하고 최종 매핑에는 포함하지 않았습니다.

## 화면에서도 수집 범위가 보이도록

처음의 임상시험 0건 표시를 고치기 위해 **ASK1 활성 탐색과 Selonsertib 연결 사례를 별도 탭으로 나눴습니다.** 활성 목록에서는 이름·동의어·ID로 검색하고 측정 유형과 최소 레코드 수로 범위를 좁힐 수 있습니다. 대표명이 없는 물질은 ChEMBL ID로 표시했습니다.

숫자를 읽는 기준도 화면과 설명에 함께 반영했습니다.

- **9/11**은 이번에 수집한 임상시험의 매칭 결과입니다. 정확도나 전체 ASK1 임상시험의 수집률을 나타내지 않습니다.
- IC50·Ki와 실험 조건이 다른 값을 하나의 약효 순위로 묶지 않았습니다.
- Open Targets의 표적 연관 근거를 개별 화합물의 치료 효과로 해석하지 않았습니다.

신약 후보나 임상 개발 성공 가능성을 예측하는 것은 이번 작업의 범위에 포함하지 않았습니다.

## 확인한 결과와 보류한 판단

**2026년 9월 11일 기록 기준 오프라인 테스트 43개가 통과했습니다.** 수집·정제·적재, PDF 근거 검증, 스냅샷 덮어쓰기 방지와 화면의 검색·필터·페이지 이동을 확인한 결과입니다.

AI 도구에는 오류 원인과 대안을 물었고, 설명을 바탕으로 방향을 정한 뒤 코드 수정과 검증을 이어갔습니다. 별도 LLM API 에이전트 서버를 만든 작업은 아닙니다.

완성한 것은 세 API의 자료를 원본·정제·조회 계층으로 연결한 파이프라인과 스냅샷 조회 화면입니다. **수집한 범위, 연결이 확인된 결과, 아직 검토 중인 근거를 함께 남겼습니다.**
